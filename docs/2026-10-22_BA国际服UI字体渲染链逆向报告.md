# Blue Archive 国际服（Steam）UI 字体渲染链逆向与替换报告

日期：2026-10-22 · 平台：Windows 10 · 引擎：Unity 2021.3.56f2（UnityFS v8）

> 本文整理对 Blue Archive 国际服客户端 UI 字体渲染链的逆向分析结论，
>
> 以及在此基础上的字体替换方案与开源工具 [BAFR](../src/bafr/) 的实现要点。
>
> 所有结论均在实机验证：替换后繁简共用字（门/骨/与等）字形呈简体写法。

## 1. 目标

将繁中 UI 字体 NotoSansTC（思源黑体 TC 版）替换为思源黑体 SC 版，
使繁中界面与汉化文本（ExcelDB 繁转简）的字形风格统一。
替代早期「改 TMP 字体」的无效方案——需先弄清真实的字体渲染路径。

## 2. 渲染链逆向结论

### 2.1 语言字体映射：ui-font 包内的 BundleFonts

- `Preload/Windows/ui-font-_mxload-*.bundle` 内含 MX 框架的语言字体映射：
  四个 MonoBehaviour（BundleFontTw/En/Kr/Th），各持有 **Normal/Bold 两个 PPtr**；
  其 MonoScript 类名为 `BundleFonts`，语言代码来自关联 GameObject 的名字
  （`BundleFontTw` → `tw`）。
- 映射关系（当前版本实测）：

| 语言 | Normal | Bold | 所在物理包（CAB） |
|---|---|---|---|
| tw | NotoSansTC-Medium | NotoSansTC-Bold | CAB-a657a…（prolog…_842690403） |
| en | NotoSans-Regular | NotoSans-Bold | CAB-e92064…（prolog…_3487395783） |
| kr | MainFont | MainFont_Bold | CAB-66213…（prolog…_2386780975） |
| th | RSU_BOLD | RSU_BOLD | 同 en |

### 2.2 主 UI 文本走 legacy Font，不经过 TMP

- TMP 资产（`GameData/Windows` 的 mxcommon asset bundle）仅用于少数 TMP 文本；
  其 `U-OTF-*` 的 `m_SourceFontFile` 为空、externals 指向 Preload 的字体包。
- **主 UI 文本的渲染路径是 BundleFontTw → legacy Font 资产（NotoSansTC）**。
  这是「TMP 方案无效」的根因：改 TMP 字体对主 UI 文本没有任何影响。

### 2.3 externals 解析的两个坑

1. PPtr 的 `m_FileID > 0` 时经 `externals[m_FileID - 1].path` 解析，
   形如 `archive:/CAB-xxx/CAB-xxx`——**外部引用按 SerializedFile 名（CAB-xxx）索引，
   与物理文件名无关**。
2. CAB-xxx 对应的物理 bundle **可能不在同目录**：ui-font 包的三个 externals
   全部位于 `Preload/Windows` 的 prolog 字体包，而非 `GameData/Windows`。
   全库扫 CAB 时两个目录都要覆盖。

## 3. Bundle 完整性机制

- `catalog_Remote.json`（LocalLow）**没有 m_Crc 字段**，catalog 层不做校验；
- 客户端仅按**文件名尾 CRC 自校验**：修改 bundle 后须追加 4 字节修正，
  使整文件 CRC32 等于文件名尾的十进制数值
  （如 `…_842690403.bundle` → 目标 CRC `0x323C5563`）。
- 修正算法：对 `data + 4×00` 计算 CRC，由 GF(2) 多项式求逆得到 4 字节修正尾，
  实现见 [crc.py](../src/bafr/utils/crc.py)（`apply_crc_fix`）。
- 附带结论：原版文件本身已含该 4 字节修正尾（文件 size > UnityFS 头部记录值），
  解析时可用头部 `size` 字段而非文件长度定位数据，天然兼容修正尾。

## 4. 替换方案

### 4.1 Font 资产 typetree 补丁

对目标 Font 对象（legacy Font，UnityPy 下 `type.name == "Font"`）：

```python
tree = obj.read_typetree()
tree["m_FontData"] = otf_bytes            # 替换字体数据
tree["m_FontNames"] = ["Source Han Sans SC Medium"]  # 替换家族名
for field in ("m_CharacterRects", "m_CharacterInfo"):  # 字形缓存，按存在性清空
    if field in tree:
        tree[field] = []
obj.save_typetree(tree)                   # UnityPy 写回 API 是 save_typetree
```

要点：

- **其余度量字段全部不动**。NotoSansTC 即思源黑体 TC 版，与 SC 版 UPM/asc/desc
  一致，零布局风险；
- 字形缓存字段名随包版本不同：Prolog 包为 `m_CharacterRects`，
  GameData 包为 `m_CharacterInfo`，改前先看实际字段；
- 保存用 `env.file.save()`（无压缩，UnityFS flags 64/64），再按 §3 做 CRC 修正；
- 产物与原文件同尺寸级别（~33.5MB），放回 `Preload/Windows/` 同名替换即可。

### 4.2 输入约束

仅接受单个 sfnt 字体文件（otf 头 `OTTO` / ttf 头 `\x00\x01\x00\x00`），
不支持 ttc / 可变字体。

### 4.3 ExcelDB 文本汉化（另一条修改线）

文本内容汉化与字体替换相互独立：`GameData/TableBundles/ExcelDB.db` 为 sqlcipher
加密库，逐表扫描文本列做繁→简替换（短语表 + 单字映射），产物同样以
`apply_crc_fix` 对齐文件名 CRC 后替换。

## 5. 工程实现：BAFR

完整流程已封装为 CLI 工具 [BAFR](https://github.com/)（本文仓库 `src/bafr/`）：

```
bafr scan     # 枚举 BundleFonts 语言映射清单（语言无关，不硬编码 Tw/En/Kr/Th）
bafr replace --lang tw --normal X.otf --bold Y.otf [--output-dir work]
```

实现要点（模块对照）：

| 模块 | 职责 |
|---|---|
| [naming.py](../src/bafr/naming.py) | bundle 文件名解析（date/CRC/prefix） |
| [searching.py](../src/bafr/searching.py) | 前缀定位 ui-font 包、CAB→物理包搜索、映射缓存 |
| [bundle.py](../src/bafr/bundle.py) | Bundle 安全加载（trailing bytes 检测）、保存 + CRC 修正、轻量 CAB 名解析 |
| [fonts.py](../src/bafr/fonts.py) | BundleFonts 解析、Font 替换、产物自检 |
| [cli.py](../src/bafr/cli.py) | Tap 命令行 |

### 5.1 CAB→物理包定位：不做全量解压

externals 只给 CAB 名，catalog 又没有 CAB→物理文件的映射，定位物理包只能全目录扫描。
若对每个 bundle 做全量解压（UnityPy `load`），2.6 万个文件需要分钟级耗时。
实测优化为**只解析 UnityFS 头部与 blockinfo**（内部文件名表所在，通常仅几百字节）：

- 头部布局：`UnityFS` + version(u32) + version_player/engine(cstring)
  + size(i64) + compressed/uncompressedBlocksInfoSize(u32) + flags(u32)；
- 引擎版本 ≥ 2020.3.34（及 2021.3.2 / 2022.1.1 等分界，与 UnityPy 语义一致）
  后 flags 为新枚举；**头部版本 ≥ 7 时 blockinfo 起始 16 字节对齐**
  （实测该包：header_end=50 → 对齐到 64 后才能正确解压）；
- flags 低 6 位为压缩类型：0=none / 1=LZMA / 2,3=LZ4(LZ4HC)；
- blockinfo 布局：hash(16B) + 块表（**每条 10 字节**：u32+u32+u16，不是 12）
  + 节点表（offset i64 / size i64 / flags u32 / name cstring）；
- 加密包（`UsesAssetBundleEncryption`）与未知格式返回失败，回退全量加载。

单次冷扫描 26288 个 bundle 降至秒级，且无缓存也能接受；
另加按路径+大小+mtime 校验的 CAB 映射缓存，游戏更新后自动失效重扫。

### 5.2 可复现性

以文档操作前后的 bundle 作为测试资产，替换流程产物与人工流程产物
**逐字节一致**（CRC 修正含在内），见 [test_reproduce_font_replace.py](../tests/test_reproduce_font_replace.py)。

## 6. 踩坑清单

1. **先确认渲染路径再动手**：TMP 方案无效的根因是主 UI 文本走 legacy Font；
2. **externals 容易看错对象**：CAB-e92064/66213/a657a 是 ui-font 包的 externals，
   且物理包在 Preload 而非 GameData 目录；
3. **catalog 无 CRC 校验**，只有文件名尾 CRC 自校验；
4. **UnityPy API 版本差异**：写回是 `save_typetree`；字形缓存字段名随包版本不同；
5. **运行时 catalog 在 LocalLow**，但 bundle 本体由客户端直读 GameData/Preload 目录；
6. **游戏禁用 Unity 日志**（无 Player.log），排查只能靠静态分析 + 截图对比；
7. **UnityFS blockinfo 细节**：头部 v7+ 需 16 字节对齐；块表条目 10 字节；
   BlockInfoAtTheEnd 时用头部 size 字段定位（兼容 CRC 修正尾）。

## 7. 回滚

还原备份的目标 bundle（与 ExcelDB 原件）即可，无持久化状态残留。
